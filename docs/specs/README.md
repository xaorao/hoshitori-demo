# Specifications

The rules the code is built to, in the order a reader usually wants them.

| Start with | What it holds |
|---|---|
| `ARCHITECTURE.md` | the whole system: processes, boundaries, flows, and what the structure does and does not settle |
| `FORECAST_SETTLEMENT_CONTRACT.md` | the normative contract: how a forecast is defined, committed, settled and compared fairly (referred to in the code as "the contract", by section) |
| `LEDGER_SPEC.md`, `VERIFICATION_SPEC.md`, `VERIFIER_THREAT_MODEL.md`, `TRANSPARENCY_LOG_SPEC.md` | the record, its signatures and time-stamps, the offline verifiers and what they cannot prove |
| `CYCLE_RUNNER_SPEC.md`, `GATEWAY_DESIGN.md`, `DISCOVERY_MANIFEST_SPEC.md`, `ASSET_REGISTRY_SPEC.md`, `DATA_PROVENANCE.md`, `DOMAIN_MODEL.md` | the league's cycle, its one network door, how candidates and assets are identified, and how evidence is recorded |
| `RULES_ARM_SPEC.md`, `AGENT_PROTOCOL.md`, `SIMULATOR_SPEC.md`, `GROUNDING_CONTRACT.md`, `CLAIM_GRAPH_SPEC.md`, `EVIDENCE_CHALLENGE_SPEC.md` | the agents, the practice book, how an answer is held to its evidence, how a claim is cut into parts, and the evidence challenge |
| `SECURITY_MODEL.md`, `PRIVACY_DATA_FLOWS.md`, `OPERATIONS_ARCHITECTURE.md`, `ACCESSIBILITY_SPEC.md`, `UX_SPEC.md` | security, privacy, operations, accessibility and the interface |
| `INVARIANTS.md`, `PROOF_MATRIX.md` | the checkable properties and the evidence each one names (the matrix is generated by `scripts/proof_matrix.py`) |
| `SPEC_MATRIX.md` | each numbered section of the security, privacy and operations specifications with the checks that hold the code to it, or why none exists (generated by `scripts/spec_matrix.py`) |
| `ACCESSIBILITY_MATRIX.md` | each binding criterion of the accessibility specification with the checks that hold the pages to it, or why none exists (generated by `scripts/accessibility_matrix.py`) |
| `CONTRACT_MATRIX.md` | each numbered section of the contract with the checks that hold the code to it, or why none exists (generated by `scripts/contract_matrix.py`) |
| `RUBRIC_MATRIX.md` | each line of the published rubric, the page that bears on it, the checks that hold the page to what it says and what it does not show (generated by `scripts/rubric_matrix.py`) |
| `DECISIONS.md`, `CONTRACT_FINDINGS.md` | the choices between alternatives (`ADR-nnn`) and what building against the contract changed (`CF-nn`) |

A status word is one of DESIGNED, IMPLEMENTED, TESTED and INTEGRATED; the state of each unit of the code, with its evidence and its limit, is `../STATUS.md`. Where a document says a thing is not verified, it is not.
